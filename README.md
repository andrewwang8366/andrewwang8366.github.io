# andrewwang8366.github.io

用户站（GitHub Pages 根域）。当前**未承载任何线上内容**，仅作占位与后续整合的落点。

## 为什么会有这个仓

2026-10-20 排查「25 个 `*_public` 隐私政策站能否合并成一个仓」时做的可行性验证。
结论：**技术上可行，但没有执行**。

### 已实测的事实

| 验证项 | 结果 |
|---|---|
| 用户站能否服务任意子路径（如 `/element_island_public/`） | ✅ 能 |
| `_` 开头目录能否访问 | ✅ 加 `.nojekyll` 后可以（否则被 Jekyll 忽略） |
| 同名项目站存在时谁优先 | **项目站优先**，用户站的同名目录被忽略 |

第三条是关键：把 25 个站内容放进本仓后，只要那 25 个项目仓还在，URL 仍由项目站提供；
要真正「合并成 1 个仓」，必须**先删掉 25 个项目仓**。

### 为什么没执行

这 25 个站的 URL 被写进了各 App 的 `store/asc_meta.json`：
`privacyPolicyUrl` / `supportUrl` / `marketingUrl` —— 是**提交给应用商店审核的地址**。
删仓重建期间若有审核机器人或用户访问，会直接 404，属于合规风险，需人工决策后执行。

### 如果以后要做，步骤

1. 把 25 个 `*_public` 的内容按 `<repo名>/` 放进本仓根目录，加 `.nojekyll`
2. 逐个 `gh repo delete <name>_public`，每删一个立刻 `curl -I` 验证对应 URL 仍 200
3. 全部通过后，把各 App 的 `asc_meta.json` 指向改为无需变更（URL 不变）
